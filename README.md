# 乐谱反复段展开工具

供排练使用的 Web 应用：逐行输入小节编号与反复记号，自动校验并展开为实际演奏顺序，
页面展示演奏序号、原小节编号、源行号、实际速度（BPM）和每次演奏的起止时间（毫秒），
并可下载同内容的 CSV；还支持逐行填写“演奏序号=BPM”的临时变速方案（展开与拍点查询共用），
以及按起止毫秒查询时间窗内的节拍点（时间、演奏序号、原小节编号、拍序、首拍标记）。

## 启动

一条命令完成构建并启动：

```bash
docker compose up --build
```

容器启动时会自动安装依赖（`pip install -r requirements.txt`）并启动应用。

## 访问

- 网页：浏览器打开 <http://localhost:5000>
- API：同样经由 5000 端口访问
  - `POST http://localhost:5000/api/expand`，请求体
    `{"input": "小节编号逐行文本", "tempo": "临时变速方案（可选）"}`
  - `POST http://localhost:5000/api/beats`，请求体
    `{"input": "...", "tempo": "...", "start_ms": 0, "end_ms": 1000}`
  - `tempo` 为逐行 `演奏序号=BPM` 的文本，两个接口共用同一方案；
    省略或为空字符串时不启用临时变速

## 配置

| 环境变量 | 默认值 | 说明 |
| -------- | ------ | ---- |
| `PORT`   | `5000` | 应用监听端口（修改后请同步调整 compose 的端口映射） |

## 输入格式

每行一个小节编号：

- 编号前加 `|:` 表示反复起点
- 编号后加 `:|xN` 表示反复终点，`N` 为重复次数（2~9）
- 反复段允许嵌套；空行会被忽略
- 行末可附时间标记 `[拍数@BPM]` 或 `[拍数]`：
  - 只写 `[拍数]` 时不切换速度；完全不写标记时拍数默认为 4
  - 带速度的小节在每次演奏到时先切换速度，再累计时长
  - 未标速度的小节沿用上一演奏小节的速度，初始速度为 120 BPM
  - 拍数与 BPM 必须为正整数

示例：

```
1[4@120]
2
|:3
4[2]
|:5
6:|x3
7:|x2[4@90]
8
```

展开结果：`1 2 3 4 5 6 5 6 5 6 7 3 4 5 6 5 6 5 6 7 8`（共 21 小节）。

## 临时变速方案

在乐谱输入下方逐行填写 `演奏序号=BPM`（均为正整数），展开与拍点查询共用本方案：

- 演奏序号按反复展开后的实际轮次计数（即结果表中的“演奏序号”，从 1 开始）
- 演奏到指定轮次时临时速度优先于该小节的原谱速度
- 临时速度继续传给后续未标速小节；遇到下一处原谱显式速度（`[拍数@BPM]`）
  或下一条临时变速时重新切换
- 重复序号、序号超出展开范围或格式错误，都会定位到方案中的具体行号

例如在上述乐谱中填写：

```
3=144
12=100
```

则第 3 个演奏小节起按 144 BPM；第 11 个演奏小节（小节 7，原谱 90 BPM）先切回 90，
第 12 个再按 100 BPM，之后的小节沿用 100。

## 排练时间轴

每个演奏到的小节按 `拍数 × 60 / BPM` 秒累计时长，时间轴从 0 开始；
结果中每个小节的起止时间与实际速度（BPM）单位分别为毫秒和拍/分钟，
累计时保留完整精度，起止时间输出时四舍五入到最近毫秒。
不启用临时变速时，上例前 10 个演奏小节为 120 BPM，第 11 个（小节 7）起切换为
90 BPM，总时长 47000 毫秒。

## 节拍点查询

在展开结果下方输入起止毫秒，即可列出时间窗内的每个拍点：
时间（毫秒）、演奏序号、原小节编号、拍序与首拍标记。

- 时间窗按左闭右开 `[起始, 结束)` 处理
- 落窗判断使用未取整的累计时间，展示毫秒仍四舍五入到最近毫秒
- 反复回跳后，未标 BPM 的小节沿用上一实际演奏小节的速度
- 拍点查询与展开使用同一速度轨迹，包括同一份临时变速方案
- 查询按小节跨度跳过窗外拍点；窗内拍点超过 5000 时停止并指出对应源行

## 校验规则

- 格式错误：定位到具体输入行
- 拍数与 BPM 必须为正整数，错误定位到源行
- 小节编号必须唯一，重复时指出首次出现的行号
- `|:` 与 `:|xN` 必须配对，未配对时定位到对应行
- 临时变速方案每行必须为 `演奏序号=BPM`，演奏序号与 BPM 必须为正整数，
  错误定位到方案行号
- 临时变速的演奏序号不得重复，重复时定位到方案行号；
  序号超出展开后的实际轮次范围时，定位到方案行号并提示展开总数
- 展开超过 5000 小节时停止，并指出导致超限的源行
- 节拍点查询的起止毫秒必须为数字，起始不为负且结束大于起始；
  时间窗内拍点超过 5000 时停止，并指出对应源行

错误返回中，临时变速方案产生的错误带有 `"source": "tempo"`，`line` 为方案文本的行号；
乐谱错误不带该字段，`line` 为乐谱行号。

## 本地开发（不使用 Docker）

```bash
pip install -r requirements.txt
python app.py
```

## 项目结构

```
app.py               Flask 应用与 API
repeats.py           反复段解析、校验、展开、排练时间轴与节拍点查询
templates/index.html 前端页面（原生 HTML/JavaScript）
requirements.txt     Python 依赖
Dockerfile           镜像构建（依赖随容器启动安装）
docker-compose.yml   Compose 编排
```
